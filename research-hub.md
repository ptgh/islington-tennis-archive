## Booking and integration limits

- Existing official booking links should remain the transaction destination. Better's operator page instructs users to register and book; it does not establish an availability API available to this project. Its private-coaching list asks players to arrange directly with the coaches. Source: https://www.better.org.uk/leisure-centre/london/islington/islingtontc/tennis
- Suitable initial calls to action: **Find a court time**, **View lessons**, **Enquire about coaching**, **Arrange a restring**. These accurately describe hand-offs; avoid “Confirmed”, available slot counts or instant checkout without a real provider response.
- Provider-managed booking, membership checks, payments, refunds and cancellation rules should stay with the provider in this incremental hub. No public booking API, partnership access or inventory synchronisation was verified here.
- A future in-app slot search requires explicit operator integration discovery. A designed booking form alone cannot establish court availability or reserve a court.
- Animation should be described as a miniature neighbourhood/illustration. Players on a court, buses and pedestrians must not imply live occupancy, real-time transport or venue opening status.
